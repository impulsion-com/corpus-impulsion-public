# Couverture des extensions

> **Plateforme :** Google Ads
> **Catégorie :** Composants
> **Type :** Checklist
> **Mis à jour :** 2026-05-07

## Objectif

Valide que la couverture des extensions est complète, correctement configurée et apporte une valeur distincte au-delà du texte RSA.

---

## Ce que cette checklist valide

Cette checklist confirme :

- La présence des extensions principales requises
- Les quantités minimum sont respectées par type d'extension
- Les exigences de qualité sont respectées par type d'extension
- L'adéquation des extensions situationnelles est évaluée
- Pas de message en double entre les assets

Cette checklist ne couvre **PAS** :

- Les options de contenu des extensions (Voir : [Extension Leverage Catalog](<Composants - Utilisation des extensions.md>))
- Les paramètres d'assets automatisés (Voir : [Automated Assets Control Guidelines](<Composants - Contrôle des assets automatisés.md>))
- Les instructions d'exécution pas à pas

---

## Quand l'utiliser

Exécuter cette checklist :

- Après avoir complété la configuration des extensions pour de nouvelles campagnes
- Lors de l'audit de campagnes existantes pour des lacunes de couverture
- Avant le lancement de campagnes Performance Max

---

## Checklist

### Extensions principales

- [ ]  Liens annexes : 4-8 actifs, couvrant différentes intentions utilisateur
- [ ]  Liens annexes : Descriptions ajoutées, URLs fonctionnelles, pas de duplication avec les titres RSA
- [ ]  Callouts : 4-8 actifs, chacun mettant en avant un bénéfice distinct
- [ ]  Callouts : Mix de catégories (confiance, valeur, rapidité, fonctionnalités, risque)
- [ ]  Structured Snippets : 2+ headers actifs avec 4+ valeurs spécifiques chacun
- [ ]  Extensions Image : 3-5 images haute résolution (1200x1200 min), pas de texte excessif
- [ ]  Nom de l'entreprise : Défini, approuvé, correspond au nom légal/marque
- [ ]  Logo de l'entreprise : Carré haute résolution (1200x1200), lisible en petite taille

### Extensions situationnelles

- [ ]  Promotion : Évaluée ; si vente active → extension créée avec dates configurées
- [ ]  Prix : Évalué ; si prix compétitifs → 3-8 articles avec prix précis
- [ ]  Appel : Évalué ; si les leads (prospects) téléphoniques ont de la valeur → extension avec planification et reporting
- [ ]  Lieu : Évalué ; si les emplacements physiques importent → GBP lié et vérifié
- [ ]  Formulaire de lead : Évalué ; si lead gen principal et compromis de volume acceptable → en test
- [ ]  Message : Évalué ; si la vente conversationnelle convient → asset créé, pas de plateforme dans les titres
- [ ]  App : Évalué ; si les téléchargements sont stratégiques et ne cannibaliseront pas le web → asset créé

### Absence de duplication

- [ ]  Les liens annexes ne répètent pas les titres RSA
- [ ]  Les callouts ne répètent pas les titres RSA ni le texte des liens annexes
- [ ]  Le contenu promotion n'est pas dupliqué dans les callouts

### Statut technique

- [ ]  Toutes les extensions affichent le statut "Approuvée"
- [ ]  Aucun statut "Limitée" ou "Refusée" sans investigation
- [ ]  Les extensions promotion ont les bonnes plages de dates
